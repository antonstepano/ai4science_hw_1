# Домашняя работа 1 — «Среда и контекст»
## Проект: моделирование воздействия лунной пыли на элементы лунной станции

## 1. Цель и исследовательский контекст

Проект создаёт персональную исследовательскую среду для темы воздействия лунной пыли на элементы поверхностной лунной станции. Полная цепочка модели: **источники пыли → поля и электризация → транспорт → контакт/удар → накопление/повреждения → изменение свойств → защита и испытания**.

ДЗ 1 «Среда и контекст» решает задачу построения этой среды: инвентаризация локальной библиотеки, расширение проверенными внешними источниками, построение небольшого графа понятий, работающий поиск по локальному контексту, стартовая матрица параметров для будущих моделей и отчёт с приложенным `AGENT.md`.

Триада курса **Инференс → Контекст → Верификация** реализована так: инференс — извлечение параметров из источников; контекст — локальная библиотека + граф понятий + онтология; верификация — детерминированная проверка `checks/check_hw1.py --strict` и независимая сверка численных значений с текстом PDF.

## 8. Первый цикл «порождение → проверка»

Цикл «порождение → проверка» реализован на каждом этапе:

1. **Порождение:** извлечение численных параметров из локальных PDF (например, потенциал поверхности днём +10 В, ночью −100…−1000 В из SRC-L001).
2. **Проверка:** сверка каждого значения с текстом PDF по локатору (страница/таблица/рисунок). Значения без локатора помечены `locator_unavailable`.
3. **Регистрация:** каждое значение записано в `results/parameter_evidence.csv` с `source_id`, `locator`, `evidence_type` (MEASURED/DERIVED/SIMULATED/LITERATURE_ESTIMATE/ASSUMED), условиями и материалом.
4. **Независимая проверка:** `python checks/check_hw1.py --strict` — детерминированная проверка готовности.

Пример цикла: значение «потенциал поверхности +10 В в подсолнечной области» (SRC-L001, p.10, PE-027) порождено из текста, проверено по PDF, зарегистрировано с типом MEASURED и локатором p.10.

## 9. Стартовая матрица параметров для будущих моделей

Примеры:

- **Блок 1 (источники):** скорость ускорителя до 3 км/с (SRC-L002, p.1, PE-014); радиус частиц ровера 18–45 мкм (SRC-L003, p.2, PE-017);

## 10. DATA GAP, противоречия и ограничения

**DATA GAP (блокирующие расчёт):**
- Поверхностная энергия и параметры JKR/DMT для реальной лунной пыли (сложная форма, шероховатость) — численно не представлены в локальной библиотеке.
- Распределение заряда по размеру для реального реголита (не SiO₂) в лунных условиях.
- Коэффициенты реституции (sticking/rebound) для лунной пыли при разных скоростях и углах удара.
- Количественные данные по деградации солнечных панелей/радиаторов от осаждения пыли (только качественные описания Apollo).
- Параметры EDS (эффективность удаления, пороговые поля) для конкретных материалов.

**Противоречия (зафиксированы, не усреднены):**
- Средний размер пыли: SRC-L001 даёт 40–100 мкм (Carrier 1973), SRC-L005 — ~70 мкм. Разные выборки/методы; обе версии в PE-004/PE-006.
- Скорости ускорителя: SRC-L002 до 3 км/с, SRC-L005 400–1550 м/с. Разные установки и диапазоны размеров.
- Потенциал ночной стороны: −100 В (высокие широты) vs −200…−1000 В (плазменный слой) vs −4 кВ (солнечный максимум). Разные условия; все в PE-028/029/030.

**Ограничения:**
- Внешние источники верифицированы по метаданным (`verified_metadata`), но не все имеют открытый полный текст; численные выводы из них не делались без доступного текста.
- SRC-L004 (пылевая плазма) — методический фон, не лунно-специфичен.
- Лабораторные эксперименты (SRC-L007) на SiO₂, не на реголите; перенос на лунные условия требует учёта адгезии и гравитации.

## 5. Протокол работы
Режим — конвейер «локальный контекст → расширение литературы → доказательства → граф → проверка → отчёт».

1. Выполни `python scripts/preflight.py` и прочитай его отчёт.
2. Инвентаризируй локальные PDF по `library/local_manifest.csv`; сверь DOI/заголовок по первой странице или локальному тексту.
3. Создай/обнови `results/sources.csv`: все локальные источники + не менее 10 релевантных внешних источников. Для внешних метаданные проверить; в колонке `verification_status` использовать `verified_metadata`, `verified_oa`, `needs_review`, но не `seed_unverified` в финальном наборе.
4. Расширяй литературу по `queries/literature_search_queries.md`. Приоритет: первичные измерения/миссии → peer-reviewed статьи → NASA/другие агентства → монографии/каталоги → обзоры. Источник может быть важен даже без OA PDF, но не делай из него числовые выводы без доступного текста.
5. Для каждого локального источника создай/обнови заметку `notes/sources/<source_id>.md` со ссылками на 2–5 понятий графа и кратким указанием, какие блоки/параметры он покрывает.
6. Выполни минимум 6 запросов из `questions/local_context_queries.md` через `scripts/local_search.py`, проверь фрагменты по тексту/PDF и запиши запрос, ответ, источники, страницы и ограничения в `results/local_context_examples.md`.
7. Извлеки минимум 30 строк в `results/parameter_evidence.csv`, охватив не менее 8 разных блоков. Колонки строго по шаблону в `results/README.md`. На одной строке — одно значение/диапазон/закон при одних условиях. Противоречия сохраняй отдельными строками.
8. Обнови граф: `ontology.yaml`, `notes/concepts/`, `notes/sources/`, `notes/claims/`, `graph_view.md`. Не превращай всю литературу в граф; граф должен отвечать competency questions из ontology.
9. Напиши `report/HW1_environment_context.md` по шаблону. Обязательно: среда, карта проекта, локальная библиотека, внешний поиск, онтология/граф, примеры локального контекста, цикл порождение→проверка, первые parameter evidence, ограничения/DATA GAP, приложение с полным `AGENT.md`.
10. Перезапиши `STATUS.md`, добавь запись в `diary.md` с командой проверки и её результатом.
11. Запусти `python checks/check_hw1.py --strict`. При ошибке исправь; после двух одинаковых неудач остановись и опиши блокер.

## 6. Память
